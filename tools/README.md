# Генерация диаграмм

Один источник — два представления. BPMN-модели описаны декларативно, из них
собираются валидный BPMN 2.0 XML и Mermaid-схема для markdown.

```bash
python3 tools/build_diagrams.py
```

Зависимостей нет: только стандартная библиотека Python 3.10+.

## Файлы

| Файл | Назначение |
|---|---|
| [bpmn_gen.py](bpmn_gen.py) | Модель процесса → BPMN 2.0 XML с раскладкой (BPMNDI) |
| [mermaid_gen.py](mermaid_gen.py) | Та же модель → Mermaid flowchart |
| [build_diagrams.py](build_diagrams.py) | Описания всех процессов и сборка |

## Как описывается процесс

```python
Model(
    id="event_registration",
    name="Регистрация участника на мероприятие",
    pool_name="Регистрация на мероприятие через Telegram",
    lanes=[
        Lane("Lane_participant", "Участник", rows=1),
        Lane("Lane_bot", "Telegram-бот (FSM)", rows=2),
    ],
    nodes=[
        Start("Start_deeplink", "Переход по deep link", "Lane_participant", 0, kind="message"),
        Task("T_resolve", "Определить мероприятие", "Lane_bot", 1, kind="service"),
        Gateway("G_capacity", "Есть свободные места?", "Lane_bot", 2),
    ],
    flows=[
        Flow("Start_deeplink", "T_resolve"),
        Flow("T_resolve", "G_capacity"),
    ],
)
```

Координаты не задаются вручную: узел получает дорожку, номер колонки и,
при необходимости, строку внутри дорожки. Всё остальное — размеры, отступы,
точки маршрутов связей — считает раскладчик.

Обратные связи (возврат на предыдущий шаг) маршрутизируются под нижней
границей задействованных узлов, вертикальные — по центрам.

## Подстановка схем в markdown

В `bpmn.md` размечаются места для схем:

```markdown
<!-- diagram:01-registration -->
<!-- /diagram -->
```

`build_diagrams.py` подставляет между маркерами Mermaid-блок, собранный из той
же модели, что и одноимённый `.bpmn`. Повторный запуск переписывает блок
заново — расхождение между документом и исходником невозможно.

## Проверка результата

Все модели прогнаны через `bpmn-moddle` — парсер, на котором работает bpmn.io.
Проверяется:

- уникальность идентификаторов элементов;
- каждый узел ровно один раз указан в дорожке;
- связность: у каждого узла кроме стартового есть входящая связь, у каждого
  кроме конечного — исходящая;
- наличие `BPMNShape` для каждого узла и `BPMNEdge` для каждой связи —
  без этого диаграмма откроется пустой.

Mermaid-схемы проверены парсером `mermaid.parse()`.
