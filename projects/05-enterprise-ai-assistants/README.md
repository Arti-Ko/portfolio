# Enterprise AI-помощники для страховой компании

`ENTERPRISE / INSURTECH` · системный анализ и solution design ·
on-premises LLM, RAG, Knowledge Graph, OCR

Четыре параллельных AI-продукта в закрытом контуре крупной страховой
компании: умный поиск по нормативной базе, согласование медицинских
назначений, паспорт проверки контрагентов и помощник по закупкам.

## Задача

Компания вышла на закрытый тендер по ИИ-трансформации четырёх процессов
сразу. Жёсткое ограничение, определившее всю архитектуру: **on-premises
only** — никакого облачного ИИ, только open-source модели в контуре
заказчика. Причина не в моде на импортозамещение: через эти процессы
проходят медицинские данные застрахованных и коммерческая тайна по
контрагентам, и отправлять их во внешний API нельзя ни при каких условиях.

Второе ограничение — объяснимость. Ответ вида «система считает, что
назначение не согласовано» не принимается ни врачом, ни службой
безопасности. Каждое решение должно иметь прослеживаемое обоснование.

## Четыре продукта

| Продукт | Боль | Ключевое решение | Оценка |
|---|---|---|---|
| **Умный поиск по ЛНА** | ~2000 локальных нормативных актов, 70% — сканы; поиск нужного пункта занимает часы | On-premises RAG, гибридный поиск (векторный + BM25), обязательные ссылки на источник | ~11 млн ₽ / 22 нед |
| **Согласование медицинских назначений** | Врач вручную сверяет протокол клиники с клиническими рекомендациями: 5–10 минут на протокол | OCR с сохранением структуры + NER + движок правил на графе МКБ-10 и КР | ~13 млн ₽ / 24 нед |
| **Паспорт проверки контрагентов** | Сотрудник СБ обходит вручную 30+ государственных реестров | Оркестратор коннекторов + скоринг риска + сводный отчёт | ~8–12 млн ₽ / 16–18 нед |
| **Помощник по закупкам** | Тендерная документация приходит с размытыми требованиями и несоответствием ТЗ и форм КП | LLM с длинным контекстом + агентный аудит пакета документов | ~11,5 млн ₽ / 24 нед |

Общий бюджет программы — порядка 45 млн ₽.

## Что сделано как системным аналитиком

- **Технические паспорта по всем четырём продуктам** — контекст, границы,
  сценарии использования, критерии приёмки
- **Архитектурные обоснования** — выбор класса моделей, векторной базы,
  подхода к OCR по каждому продукту с зафиксированными trade-off
- **Три раунда Q&A с поставщиками** — уточнение требований, сбор
  ограничений, проверка выполнимости заявленных метрик
- **Требования информационной безопасности к ИИ** — модель угроз для
  on-premises LLM: prompt injection, jailbreak, утечка данных через
  контекст, отравление базы знаний
- **Общие требования и бюджетные оценки** по программе целиком
