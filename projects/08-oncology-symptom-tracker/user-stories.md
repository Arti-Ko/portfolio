# User Stories — Трекер симптомов для онкопациентов

4 эпика, 16 историй. Приоритизация по MoSCoW, оценка в story points,
критерии приёмки в Gherkin.

Все истории написаны с учётом регуляторной границы: система информирует,
но не интерпретирует клинически — см. [discovery.md](discovery.md).

## Карта эпиков

| Эпик | Название | Историй | SP | Ценность |
|---|---|---|---|---|
| EP-01 | Дневник симптомов | 5 | 34 | Ядро продукта и источник клинической пользы |
| EP-02 | Календарь приёма препаратов | 4 | 26 | Приверженность терапии — измеримый исход |
| EP-03 | Кабинет врача | 4 | 29 | Без врача продукт не имеет канала распространения |
| EP-04 | Справочник и контент | 3 | 18 | Определяет регуляторный статус продукта |

**Итого: 107 SP.**

### Порядок поставки

Первым делом — дневник симптомов на одной нозологии. Не на всех: пока не
принято решение о фокусировке, широкий охват означает поверхностные
шаблоны, которые не дадут ни клинической пользы, ни данных нужного
качества. Одна нозология, сделанная хорошо, проверяет гипотезу; десять,
сделанных поверхностно, не проверяют ничего.

Кабинет врача идёт следом за дневником, а не после всего: без врача,
который видит результат, пациент перестаёт вести дневник через две недели.

# EP-01. Дневник симптомов

## US-01.1 — Ежедневная запись симптомов

**Как** пациент, **я хочу** отмечать самочувствие за минуту, **чтобы**
вести дневник каждый день, а не забрасывать через неделю.

`Must` · `13 SP` · зависимостей нет

```gherkin
Функция: Запись симптомов

  Сценарий: Заполнение по шаблону нозологии
    Дано у пациента указан диагноз и линия терапии
    Когда он открывает дневник
    Тогда показаны только релевантные его состоянию симптомы
    И каждый отмечается выбором из шкалы, а не вводом текста

  Сценарий: Быстрое заполнение
    Когда пациент отмечает "самочувствие без изменений"
    Тогда запись сохраняется одним действием
    И не требует прохождения всех пунктов

  Сценарий: Пропущенный день
    Дано пациент не заполнял дневник два дня
    Когда он открывает приложение
    Тогда он может внести записи задним числом с указанием даты
    И пропуск не блокирует текущую запись
```

## US-01.2 — Перевод ответа в клиническую шкалу

**Как** врач, **я хочу** видеть данные в принятой клинической шкале,
**чтобы** пользоваться ими в работе, а не переводить в уме.

`Must` · `8 SP` · после US-01.1

```gherkin
Функция: Клиническая шкала

  Сценарий: Перевод ответа пациента
    Когда пациент отмечает симптом в понятных ему формулировках
    Тогда система сохраняет и исходный ответ, и рассчитанную степень
    И врачу показывается степень по клинической шкале

  Сценарий: Изменение шкалы не ломает историю
    Дано правила перевода обновились
    Когда врач открывает прошлые записи
    Тогда исходные ответы пациента сохранены
    И история может быть пересчитана по новым правилам
```

## US-01.3 — Эскалация тревожных симптомов

**Как** пациент, **я хочу** чтобы врач узнал о серьёзном ухудшении,
**чтобы** не решать самому, когда звонить.

`Must` · `8 SP` · после US-01.2

```gherkin
Функция: Эскалация

  Сценарий: Показатель выше порога
    Когда степень симптома превышает порог для его нозологии
    Тогда лечащему врачу поднимается флаг
    И пациент видит, что информация передана врачу

  Сценарий: Флаг по динамике, а не по разовому пику
    Дано симптом второй степени отмечен однократно
    Когда выполняется оценка
    Тогда флаг не поднимается

  Сценарий: Нарастание за несколько дней
    Дано симптом усиливается третий день подряд
    Когда выполняется оценка
    Тогда флаг поднимается, даже если абсолютное значение ниже порога

  Сценарий: Система не даёт клинических указаний
    Когда пациент отмечает тяжёлый симптом
    Тогда приложение не сообщает диагноз и не назначает действий
    И показывает справочную информацию и контакт врача
```

## US-01.4 — История и динамика для пациента

**Как** пациент, **я хочу** видеть свою динамику, **чтобы** понимать, что
происходит, и обсуждать это на приёме предметно.

`Should` · `5 SP` · после US-01.1

```gherkin
Функция: История записей

  Сценарий: Динамика за период
    Когда пациент открывает историю
    Тогда он видит изменение отмеченных симптомов по дням
    И может выбрать период

  Сценарий: Выгрузка к приёму
    Когда пациент готовится к визиту
    Тогда он может сформировать сводку за период
    И показать её врачу, в том числе вне системы
```

## US-01.5 — Работа без сети

**Как** пациент, **я хочу** заполнять дневник в больнице, где не ловит
связь, **чтобы** не откладывать запись на потом.

`Could` · `5 SP` · после US-01.1

```gherkin
Функция: Офлайн-режим

  Сценарий: Запись без сети
    Дано соединение отсутствует
    Когда пациент заполняет дневник
    Тогда запись сохраняется локально
    И синхронизируется при появлении сети

  Сценарий: Эскалация откладывается до синхронизации
    Дано запись сделана офлайн и содержит тревожный симптом
    Когда связь восстанавливается
    Тогда флаг врачу поднимается с указанием фактического времени записи
```

# EP-02. Календарь приёма препаратов

## US-02.1 — Схема приёма и напоминания

**Как** пациент, **я хочу** получать напоминания по своей схеме, **чтобы**
не пропускать приёмы из-за забывчивости.

`Must` · `8 SP` · зависимостей нет

```gherkin
Функция: Напоминания о приёме

  Сценарий: Напоминание по схеме
    Дано врач назначил схему приёма
    Когда наступает время приёма
    Тогда пациент получает напоминание

  Сценарий: Подтверждение приёма
    Когда пациент отмечает приём
    Тогда факт фиксируется с фактическим временем

  Сценарий: Повтор в пределах окна
    Дано приём не подтверждён
    Когда проходит часть терапевтического окна
    Тогда напоминание повторяется
    И после окончания окна повторы прекращаются
```

## US-02.2 — Фиксация пропусков

**Как** врач, **я хочу** знать о пропусках, **чтобы** понимать, связано ли
отсутствие эффекта с самой терапией.

`Must` · `8 SP` · после US-02.1

```gherkin
Функция: Учёт пропусков

  Сценарий: Пропуск фиксируется после окна
    Дано терапевтическое окно приёма истекло без подтверждения
    Когда планировщик закрывает окно
    Тогда приём отмечается пропущенным

  Сценарий: Инструкция без указаний по лечению
    Когда фиксируется пропуск
    Тогда пациенту показывается справочная информация
    И система не рекомендует изменить дозу

  Сценарий: Пропуск можно отметить задним числом
    Дано пациент принял препарат, но не отметил
    Когда он подтверждает приём в течение суток
    Тогда запись корректируется с фактическим временем
```

## US-02.3 — Показатель приверженности

**Как** врач, **я хочу** видеть накопленный показатель, **чтобы** отличать
единичный пропуск от системной проблемы.

`Must` · `5 SP` · после US-02.2

```gherkin
Функция: Приверженность терапии

  Сценарий: Расчёт за период
    Когда врач открывает карточку пациента
    Тогда он видит долю подтверждённых приёмов за период

  Сценарий: Сигнал при падении ниже порога
    Дано приверженность опустилась ниже порогового значения
    Когда выполняется пересчёт
    Тогда врач получает сигнал

  Сценарий: Единичный пропуск не поднимает сигнал
    Дано пропущен один приём за месяц
    Когда выполняется пересчёт
    Тогда сигнал не формируется
```

## US-02.4 — Изменение схемы терапии

**Как** врач, **я хочу** менять схему приёма, **чтобы** календарь пациента
соответствовал текущему назначению.

`Must` · `5 SP` · после US-02.1

```gherkin
Функция: Изменение схемы

  Сценарий: Новая схема заменяет старую
    Когда врач назначает новую схему
    Тогда календарь перестраивается со дня вступления в силу
    И история приёмов по прошлой схеме сохраняется

  Сценарий: Завершение курса
    Дано схема имеет дату окончания
    Когда дата наступает
    Тогда напоминания прекращаются
    И пациент получает уведомление о завершении курса
```

# EP-03. Кабинет врача

## US-03.1 — Список пациентов с флагами

**Как** врач, **я хочу** видеть, кому нужно внимание, **чтобы** не
просматривать всех подряд.

`Must` · `13 SP` · после US-01.3

```gherkin
Функция: Список пациентов

  Сценарий: Приоритет по флагам
    Когда врач открывает кабинет
    Тогда пациенты с поднятыми флагами показаны первыми
    И указано, какой симптом вызвал флаг

  Сценарий: Отсутствие флагов
    Дано ни у кого из пациентов нет тревожных показателей
    Когда врач открывает кабинет
    Тогда он видит список без выделений и сводку по активности ведения дневников
```

## US-03.2 — Карточка пациента

**Как** врач, **я хочу** видеть динамику симптомов и приверженность на
одном экране, **чтобы** оценить картину за минуту приёма.

`Must` · `8 SP` · после US-03.1

```gherkin
Функция: Карточка пациента

  Сценарий: Сводка состояния
    Когда врач открывает карточку
    Тогда он видит динамику симптомов, приверженность терапии
      и последние записи

  Сценарий: Переход к первопричине флага
    Когда врач нажимает на флаг
    Тогда открывается запись дневника, вызвавшая эскалацию
```

## US-03.3 — Реакция врача на флаг

**Как** врач, **я хочу** фиксировать реакцию на флаг, **чтобы** он не
висел бесконечно и была видна история решений.

`Must` · `5 SP` · после US-03.2

```gherkin
Функция: Обработка флага

  Сценарий: Врач принимает меры
    Когда врач отмечает флаг обработанным с комментарием
    Тогда флаг снимается
    И решение сохраняется в истории пациента

  Сценарий: Флаг без реакции
    Дано флаг не обработан в течение установленного срока
    Когда срок истекает
    Тогда он выделяется в списке как просроченный
```

## US-03.4 — Подключение пациента к врачу

**Как** врач, **я хочу** приглашать своих пациентов, **чтобы** видеть
именно их и никого больше.

`Must` · `3 SP` · зависимостей нет

```gherkin
Функция: Связь врача и пациента

  Сценарий: Приглашение пациента
    Когда врач формирует приглашение
    Тогда пациент по нему подключается к наблюдению

  Сценарий: Врач видит только своих пациентов
    Когда врач открывает список
    Тогда в нём только подключённые к нему пациенты

  Сценарий: Отзыв доступа пациентом
    Когда пациент отзывает доступ
    Тогда врач перестаёт видеть его данные
    И ранее поднятые флаги закрываются
```

# EP-04. Справочник и контент

## US-04.1 — Справочник в информационно-просветительском формате

**Как** пациент, **я хочу** находить понятное объяснение своего симптома,
**чтобы** меньше пугаться и лучше понимать лечение.

`Must` · `8 SP` · зависимостей нет

```gherkin
Функция: Справочник

  Сценарий: Статья по отмеченному симптому
    Когда пациент отмечает симптом
    Тогда ему доступна связанная справочная статья

  Сценарий: Формат статьи
    Когда пациент читает статью
    Тогда она объясняет, что это за состояние и когда обращаться к врачу
    И не содержит указаний по изменению терапии
```

## US-04.2 — Ведение шаблонов по нозологиям

**Как** медицинский редактор, **я хочу** править шаблоны и справочник без
релиза приложения, **чтобы** быстро исправлять формулировки.

`Must` · `5 SP` · после US-04.1

```gherkin
Функция: Управление контентом

  Сценарий: Правка формулировки
    Когда редактор публикует новую версию статьи
    Тогда пациенты видят её без обновления приложения

  Сценарий: Версионирование контента
    Когда статья изменена
    Тогда предыдущая версия сохраняется
    И можно восстановить, какую версию читал пациент в конкретный день

  Сценарий: Новая нозология
    Когда редактор добавляет профиль нозологии с набором симптомов
    Тогда он становится доступен для назначения пациентам
```

## US-04.3 — Согласия на обработку данных

**Как** оператор данных, **я хочу** фиксировать согласия с самого начала,
**чтобы** накопленные данные можно было использовать в будущей
B2B-модели.

`Must` · `5 SP` · зависимостей нет

```gherkin
Функция: Согласия

  Сценарий: Согласие при регистрации
    Когда пациент регистрируется
    Тогда фиксируется согласие с указанием версии документа и времени

  Сценарий: Раздельные согласия
    Когда пациент даёт согласие
    Тогда обработка для оказания сервиса и передача обезличенных данных
      согласуются отдельно

  Сценарий: Отзыв согласия
    Когда пациент отзывает согласие на передачу данных
    Тогда его записи исключаются из будущих обезличенных выгрузок
```

## Definition of Ready

История берётся в спринт, если: проверено, не переводит ли она приложение
в статус медицинского изделия; согласованы формулировки, которые видит
пациент; определено, что видит врач, а что нет; для историй с данными
пациента — определён режим согласия.

## Definition of Done

Сценарии Gherkin покрыты автотестами; формулировки в интерфейсе вычитаны
медицинским редактором; проверено, что система нигде не даёт указаний по
изменению терапии; поведение при отсутствии сети проверено.
