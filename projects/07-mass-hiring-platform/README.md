# HR-платформа массового найма

`HR-TECH / ENTERPRISE` · системный анализ и пресейл ·
интеграционная архитектура, событийная шина, высокая нагрузка

Внутренний портал массового найма самозанятых и индивидуальных
предпринимателей для крупной экосистемы: сборщики заказов, курьеры,
операторы, наставники. Два инстанса под две дочерние компании группы.

## Задача

Массовый найм линейного персонала — это не рекрутинг, а конвейер. Тысячи
кандидатов в месяц, многоэтапная воронка, разные формы занятости и
разрозненные системы, между которыми данные ходят вручную. У логистического
направления сверх этого — медицинский контроль и проверка безопасности
дорожного движения, без которых человека нельзя допустить за руль.

Ручные процессы перестали справляться раньше, чем выросла нагрузка: узкое
место не в людях, а в том, что статус кандидата живёт в четырёх системах
одновременно и нигде целиком.

## Масштаб и ограничения

| Параметр | Значение | Следствие для архитектуры |
|---|---|---|
| Пользователей | 80 000 | Секционирование таблиц, отказ от полных выборок |
| Пиковая нагрузка | 100 запросов в секунду | Кеширование справочников, асинхронные проверки |
| Два инстанса | Разные дочерние компании | Общее ядро, различия в конфигурации, а не в форках |
| Персональные данные | Паспорта, медицинские заключения | Секрет-хранилище, шифрование, разграничение доступа |
| Внешних интеграций | 6 | Ни одна не должна ронять воронку целиком |

## Интеграционный контур

| Система | Профиль нагрузки | Роль |
|---|---|---|
| Событийная шина | Асинхронная синхронизация | Точки работы, историческая миграция данных |
| CRM | 5 000–10 000 запросов в сутки | Двусторонний обмен по кандидатам |
| Медицинский партнёр | 3 000 запросов в сутки | Заключения медосмотров |
| Публичный налоговый API | 2 вызова в минуту | Проверка статуса самозанятого |
| Внутренний налоговый API | 5 000 запросов в сутки | Расширенные данные |
| Секрет-хранилище | — | Ключи и доступ к персональным данным |

Два ограничения определили половину решений: **публичный налоговый API
допускает два вызова в минуту** — это меньше, чем поток кандидатов в час
пик, поэтому проверка асинхронна и очередями; **внутренний API не имеет
публичной документации** — контракт фиксировался опытным путём и обёрнут
адаптером, чтобы его изменение не расходилось по всей системе.
